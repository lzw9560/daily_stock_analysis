# A股智能分析系统 — 改进与完善计划

> 视角：资深高胜率高收益 A 股交易员 + 量化交易专家
> 定位：短线打板 / 中短线波段 / 中线趋势 / 长线价值全覆盖
> 目标：让系统从"分析工具"升级为"实战交易系统"

---

### 1.1 已有能力盘点

| 经验存储 | ✅ | ExperienceStore 辩论经验沉淀 |

### 1.2 核心短板

1. **缺少真正的资金流向分析** — 大单/主力/北向/南向资金追踪薄弱
2. **缺少盘口微观结构** — 逐笔成交、Level-2 委托队列、挂单分布缺失
3. **缺少板块/题材联动** — 个股与板块、题材之间的传导关系未建模
4. **缺少龙虎榜分析** — 机构/游资席位追踪、营业部画像缺失
5. **缺少量化因子库** — 因子挖掘、IC 分析、因子合成停留在骨架
6. **缺少实盘对接** — 目前仅为模拟组合，无法真正下单
7. **缺少策略组合管理** — 多策略并行时的资金分配、冲突检测缺失
8. **缺少盘中实时分析** — 仅盘后+竞价，盘中缺乏滚动分析能力
9. **缺少A股舆情监控** — 社交媒体仅覆盖 Reddit/X（美股），A 股舆情空白
10. **缺少可视化回测报告** — 回测结果仅有数字，缺乏权益曲线、最大回撤图等

## 二、新增模块规划

### 2.1 资金流向分析模块 (`src/services/capital_flow_service.py`)

**定位**：追踪聪明钱（Smart Money）动向

**核心功能**：
- 主力资金净流入/流出（大单/中单/小单拆分）
- 北向资金（沪股通/深股通）实时追踪
- 南向资金（港股通）追踪
- 融资融券余额变化
- 大宗交易监控
- ETF 份额变动（聪明钱信号）

**数据源**：
- AkShare：`stock_zh_a_symbol_dissemination`（主力流入）
- AkShare：`stock_hsgt_north_net_flow_in_em`（北向）
- AkShare：`stock_margin_detail_em`（两融）
- Tushare：`hsgt_top10_em`（十大成交股）

**输出**：
- 资金流向日报（纳入每日分析）
- 资金异动告警（单小时净流入 > N 亿触发）
- 资金-价格背离检测（价涨量缩但资金大幅流入 = 潜在机会）

### 2.3 板块/题材联动模块 (`src/services/sector_service.py`)

**定位**：理解资金在板块间的轮动

**核心功能**：
- 行业板块/概念板块/地域板块排行

**数据源**：

**输出**：

### 2.4 量化因子引擎 (`src/services/factor_engine.py`)

**定位**：系统化因子挖掘与管理

**核心功能**：
- 因子库建设（价值/成长/动量/波动/流动性/技术/情绪）
- IC（信息系数）分析 — 因子预测能力评估
- IR（信息比率）计算 — 因子稳定性评估
- 因子正交化 — 去除因子间相关性
- 因子合成 — 等权/IC加权/机器学习加权
- 因子衰减分析 — 各因子预测有效期
- 因子拥挤度监测 — 防止过度拥挤

**因子类别**：

| 类别 | 示例因子 |
|------|----------|
| 价值 | PE/PB/PS/股息率/企业价值倍数 |
| 成长 | 营收增速/净利润增速/ROE变化 |
| 动量 | 20日/60日/120日收益率/RSI |
| 波动 | 20日/60日波动率/ATR/布林带宽 |
| 流动性 | 换手率/量比/Amihud非流动性 |
| 技术 | MACD金叉/均线多头/筹码集中度 |
| 情绪 | 融资买入占比/新闻舆情得分/换手异常 |

**输出**：
- 因子日报（Top 强势因子/弱势因子）
- 因子组合评分（每只股票的因子综合得分）
- 因子轮动信号

## 四、架构改进

### 4.1 事件驱动架构

**当前问题**：主流程为批处理模式，盘中缺乏实时响应

**改进方案**：

```
Event Bus (Redis/Queue)
├── 数据事件 ──> 数据质量监控 / 增量更新
├── 价格事件 ──> 告警引擎 / 盘中分析
├── 成交事件 ──> 盘口分析 / 大单监控
└── 新闻事件 ──> 舆情分析 / 板块轮动
```

### 4.2 插件化策略架构

**目标**：策略即插即用，支持社区贡献

**设计**：

```python
class BaseStrategy(ABC):
    @abstractmethod
    def analyze(self, context: AnalysisContext) -> Signal:
        ...
    
    @abstractmethod
    def get_config_schema(self) -> dict:
        ...

STRATEGY_REGISTRY = {
    "breakout": BreakoutStrategy,
    "pullback": PullbackStrategy,
    "dragon_head": DragonHeadStrategy,
    # 用户自定义策略可动态注册
}
```

### 4.3 数据管道优化

**当前问题**：每次分析重新拉取数据，效率低

**改进方案**：
- 增量数据更新（仅拉取新数据）
- 数据预计算（技术指标提前算好存缓存）
- 数据版本管理（支持历史状态回溯）
- 数据质量监控（缺失值/异常值检测）

## 六、关键指标设计

### 6.1 系统级指标

| 指标 | 目标 | 说明 |
|------|------|------|
| 数据延迟 | < 3秒 | 盘中数据从产生到可用 |
| 分析耗时 | < 30秒/股 | 单股完整分析时间 |
| 告警准确率 | > 60% | 告警后5日内触发真实机会的比例 |
| 选股胜率 | > 55% | 选出股票N日上涨概率 |
| 系统可用性 | > 99% | 服务正常运行时间 |

### 6.2 策略级指标

| 指标 | 计算方式 | 目标 |
|------|----------|------|
| 年化收益 | 策略期末净值/期初净值^(365/T) - 1 | > 20% |
| 最大回撤 | 峰值到谷值的最大跌幅 | < 15% |
| 夏普比率 | (年化收益-无风险利率)/年化波动率 | > 1.5 |
| 胜率 | 盈利交易次数/总交易次数 | > 50% |
| 盈亏比 | 平均盈利/平均亏损 | > 2.0 |
| 信息比率 | 超额收益/跟踪误差 | > 1.0 |

## 七、风险与注意事项

1. **数据合规**：部分数据源（如 Level-2）需要付费授权，注意合规使用
2. **实盘风险**：实盘交易前必须经过充分回测和模拟验证，建议至少3个月纸上交易
3. **过拟合**：因子挖掘和策略优化容易过拟合，需要使用样本外数据和交叉验证
4. **系统复杂度**：新增模块会增加系统复杂度，需要注意模块间的解耦
5. **LLM 成本**：深度分析依赖 LLM，需要考虑成本控制
6. **市场变化**：A股市场风格切换快，策略需要定期评估和调整

## 八、总结

本系统的核心优势在于：
- **多Agent辩论**：从多角度分析，减少单一视角偏差
- **逻辑闭环**：信号→执行→验证→反馈→优化
- **多策略覆盖**：从打板到长线，覆盖不同交易风格
- **完善的回测体系**：策略验证有据可依

改进方向的核心思路：
- **从分析到执行**：打通从分析到实盘的最后一步
- **从盘后到盘中**：提升实时决策能力
- **从个股到板块**：理解市场整体结构
- **从人工到自动**：因子挖掘和策略优化的自动化
- **从数字到可视化**：让结果更直观

最终目标：**打造一个完整的 A 股量化交易系统，从数据→分析→决策→执行→反馈全链路覆盖。**
